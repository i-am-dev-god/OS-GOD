# Stillspace

A text-first desktop workspace with movable, resizable windows, a taskbar, a launcher, desktop shortcuts, and a customizable liquid-glass appearance. Create, edit, search, favorite, organize, export, and restore notes. Notes save locally as you type; sign in to sync across devices. Guest mode requires no account. On small screens windows expand to fit the display.

## Desktop interactions

Open notes in separate windows; drag their title bars, resize from the lower-right corner, minimize, maximize and restore with the taskbar. Open the launcher with Start, use Ctrl/Cmd+N for a new note or Ctrl/Cmd+K to search. Settings offers preset or uploaded wallpaper (PNG/JPEG/WebP under 700 KB), accent color, glass blur, editor text size, layout density, taskbar alignment, desktop shortcuts, and a motion toggle. These settings are local to the browser; the OS reduced-motion preference is also respected. Windows can be snapped left or right, and focus mode hides other windows without closing them. Ctrl/Cmd+Shift+P opens the command palette. Import a .txt file, duplicate individual notes, or export all active notes as JSON (exports are unencrypted and do not include deleted notes).

## Local development

Node 22: `npm ci`, `npm test`, `npm run dev`, `npm run build`. The development server is exposed on `0.0.0.0` for preview. The production build uses relative paths for GitHub Pages. Offline app-shell caching is enabled only in the production build; open the deployed site online first. Browser caches can be evicted, so keep backups.

## Cloud sync

The app is configured for the connected `os-god` Supabase project with its **publishable** key. The migration in `supabase/migrations/` creates a separate `memo_os_notes` table with row-level policies restricting notes to the signed-in user. It was applied to the connected project, and email sign-in was enabled on that project. Email signup requires confirmation. The configured confirmation URL is the GitHub Pages site; test sign-up after deployment. Supabase email delivery/rate limits can require further provider configuration.

Local guest notes stay local after login; open Account and select which guest items to copy. Sign-out switches to the guest workspace but **does not erase cached account notes from this browser**. Avoid shared devices or clear site data after exporting anything you need.

The client fetches notes on login, focus, reconnect, and periodically. Changes are merged by note ID and client timestamp; concurrent changes to the same note use **last timestamp wins**, and conflicting edits may be lost. Device-only history is available with the limits described below. Deletion uses retained tombstones to prevent old devices resurrecting notes. Local browser storage and cloud plans have limits; neither compression nor this app makes storage unlimited.

The app uses lossless gzip only when the base64-encoded result is smaller than the original JSON; otherwise it stores plain JSON. The storage indicator estimates serialized note payload only and excludes database overhead, metadata, tombstones, and backups. Notes are protected by Supabase row-level security and transport encryption, but are **not end-to-end encrypted**. Do not use the app for secrets requiring zero-knowledge storage.

Set `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY` at build time to target a different project. Never put a service-role/secret key in frontend code. GitHub Pages deployment uses the included workflow after changes reach `main`.

### Desktop personalization
Settings stores your wallpaper (including an optional local image), accent, glass and motion preferences, dock size and alignment, shortcut visibility, editor typeface and size, clock format, default notes view, and note sorting in this browser. The dock opens and switches windows; the menu bar opens settings, search, and the clock. Use the toolbar navigation button to hide or show the notes sidebar. Preferences stay local unless you opt in to wallpaper or shortcut visibility sync from Account; other preferences remain local.

### Appearance and navigation
Choose Light, Dark, or System appearance in Settings. The desktop includes Notes, Reminders and Settings shortcuts; note collections are inside Notes. Search the whole workspace for apps, actions, collections and note content with Ctrl/Cmd+K (or Ctrl/Cmd+Shift+P); use arrow keys and Enter to navigate results. The Notes toolbar provides a separate note-only search; Ctrl/Cmd+N creates a note, Ctrl/Cmd+Shift+J cycles open or minimized windows, and Ctrl/Cmd+Shift+M minimizes the active window. Motion can be disabled in Settings and respects the system reduced-motion setting.

The note search control expands in place when selected. The desktop appears at startup; open Notes from its desktop shortcut or the taskbar. Import and export remain in the command palette. Maximizing a window fills the usable desktop between the menu bar and taskbar; it does not request browser fullscreen. Dragging keeps a window within the usable area when its dimensions fit.

Account and sign-in open in a contextual panel near the control you selected; click outside, press Escape, or use its close button to dismiss it. The launcher also opens near its trigger. Actions use brief feedback animations, which can be disabled in Settings and respect the system reduced-motion preference.

Notes windows share one taskbar button: select it to switch between the library and open notes. Hover or focus a window’s maximize button to choose left, right, or centered layouts; click it to maximize or restore. Escape dismisses the layout menu. Settings opens in a feature-first Workspace view, with Appearance and Data & account in separate sections. Interface chrome is not selectable, while note content and form fields remain selectable.

The star launcher expands into Notes, Settings, and Account. Notes opened or created there remain in the launcher for editing; use the arrow in its header to extract the current app or note into a movable window. The back arrow or star returns to the previous launcher view, and the star closes it from the home view. Extracted Settings and Account windows appear in the taskbar while open. Ctrl/Cmd+K opens a non-modal floating search surface.

### Note history (device only)
The History button in a note shows earlier title and body checkpoints, with preview and confirmed restore. Checkpoints are captured before text changes, at most once every 30 seconds, and before restoring or replacing local text with a newer cloud copy. Up to 20 versions and 512 KiB of text are kept per note; oversized versions cannot be saved. Search can find these local versions. History is kept separately for each guest/account workspace in this browser, is not synced or included in exports, and can be lost if site data is cleared or evicted. Existing notes gain history only after editing. Cloud sync still uses last-timestamp-wins and this local history cannot guarantee recovery of every cross-device conflict.

### Reminders
Open a note and select the bell to set or clear a reminder. The top-bar bell lists upcoming and overdue notes; clear a reminder with its check mark. Search can also find reminders. Dates are entered in the device’s local time zone and stored as UTC instants. Reminder dates sync with signed-in notes and are included in JSON exports; guest data stays on the device.

Browser notifications are optional and require permission on each device. They can appear only while Stillspace is open; background tabs may be delayed, and missed reminders appear when the app is reopened. This is not a push service or an alarm when the browser is closed. Notification titles contain the note title. Delivery records are local to each browser, so multiple devices may each notify. Deleted notes do not notify; restoring a deleted note retains its reminder. Sync remains last-timestamp-wins.

### Reminders app
Open Reminders from the launcher or top-bar bell. Create standalone reminders, complete or reopen them, reschedule to an exact time or snooze for an hour or until 9 AM tomorrow, and open linked notes. Completed items remain in the Completed view; removing a note reminder does not delete the note. Standalone reminders are stored and synced with the workspace under the same account protections and last-timestamp-wins rules as notes. Guest import and JSON export include standalone reminders. Notification text is brief and includes the reminder title; it can be visible on the lock screen. Delivery still requires Stillspace to be open and browser permission.

### Share a workspace layout
Sign in and choose **Share layout** in the top bar to create an unlisted link to the visible Notes, Reminders and Settings window positions. Anyone with the link can open the layout without signing in, and opening it replaces their current window arrangement after confirmation. Note editors, note contents, reminders, account details, minimized windows, launcher views and wallpaper are not shared; recipients see their own data. Layouts adapt approximately to the recipient’s screen. Links remain available until the account is deleted; keep them private. Each account can create up to 30 layouts, each capped at 1 KiB; there is currently no link-management screen. Creating a link requires an account and internet access.

### Choose what to bring from guest mode
After signing in, open Account and choose favorites, other notes, standalone reminders, wallpaper and/or desktop shortcut visibility. Copies of selected notes and reminders sync through the existing account storage; future repeated imports skip guest items already copied by this version, including copies in Recently deleted; earlier imports cannot be identified and are not automatically removed. The guest originals remain on the device. Choosing wallpaper or shortcuts saves those choices to the account and syncs subsequent changes to those selected categories. Custom wallpaper is uploaded when selected; account preferences use owner-only row-level security but are not end-to-end encrypted. Note history is not imported. Email confirmation may be required before signing in.

### Desktop context navigation
Right-click the Stillspace interface to open app navigation, create a note, search, or show the desktop. Context Menu or Shift+F10 also opens it; use arrow keys and Escape to navigate and dismiss. Text fields and selected text retain their native menu.

### Account deletion
In Account, expand **Delete account**, enter your password and type DELETE. Recent password authentication is required by the server. Deleting the account permanently removes its cloud notes, standalone reminders, cloud preferences and layout links; this cannot be undone. Cached account notes, history and reminder delivery records on the current device are removed on success. Guest data is not deleted, and caches on other devices and provider backups may remain. Export anything you want to keep first. Only the signed-in account can delete itself.

### Shared workspaces (live view)
Choose Live room, enter a name, then create or join using a code. You switch into a separate Stillspace desktop with a persistent shared-workspace alert and the regular Notes and Reminders apps. Each participant can choose to expose no existing data, all Notes and Reminders data, or specific apps. Non-deleted selected items are sent live directly from their owner’s currently open app; room storage does not keep copies of their content. New notes or reminders created while in the shared desktop are saved in their creator’s normal workspace and are shared while that participant remains connected only if they enable sharing new items. Leaving restores the local window arrangement. Settings and window layouts remain local.

Participants can view others’ selected notes and reminders, but cannot directly edit them; each owner’s own edits are sent to the others. In room settings, each owner can change which existing apps and newly created items they share, choose whether to show coarse activity, and opt in to note edit suggestions. Suggestions are **off by default**, are visible to the room, and require the owner to review and accept each one. A suggestion is not applied if the original note changed since it was sent. Reminders do not support suggestions. This is not a character-by-character collaborative editor. Reminders from others do not trigger local notifications. Data is visible only while its owner stays connected, with updates approximately every two seconds; intermittent connections and oversized payloads can stop updates. A participant can broadcast at most 500 items and 180,000 JSON characters at once; larger selections are not sent and a status message is shown. No private notes are sent unless their app was selected or the notes were created while sharing.

Room codes are 122-bit bearer secrets; anyone with the code can receive shared content and impersonate names or data. The content is not end-to-end encrypted and passes through Supabase Realtime. Do not share sensitive content. Deleting a room invalidates its code and removes room metadata, but does not erase original notes or copies made by participants; peers may take up to 10 seconds to disconnect. The room expires after 24 hours without validation, and the hourly database cleanup removes expired metadata. Activity while the room is open renews the timer. There is a shared limit of 100 active rooms. Provider logs or backups may remain. Existing room item storage was cleared and its write API disabled.

The **Participants** button beside room settings shows the people currently broadcasting and their coarse activity (desktop, Notes, a note, Reminders or Settings). No note titles or keystrokes are included in activity. Each participant can hide their activity in room settings. The panel can be dragged; close it or drag it to the top bar to tuck it away. Presence is approximate and may disappear after a connection interruption. The room code is shared by everyone and names are self-selected, so there is no verified identity or per-person access control: the sharing choices apply to everyone with the code, and anyone can impersonate a participant or see suggestions. Only approve a suggestion if you trust the room and its content. Switching off sharing cannot retract anything already seen or copied.

Shared workspace settings also provide **Pause all my sharing**: it turns off sharing existing app data, new items, activity and suggestions at once. Items you created in the room remain visible to you. Original items remain in the personal workspace. Participants may already have seen or retained earlier content; switching sharing off cannot retract it.

### Calendar, sync health and clipboard
Reminders has a month calendar showing active standalone and note reminders in local time. Select a day to see its reminders; move your own reminder using its date control (the time is retained). Shared items are view-only. Completed reminders remain in the Completed list. Existing reminder edits can now be cancelled without saving.

Open Sync health from the top bar or workspace search. It reports browser connectivity, current sync status, the last successful account sync in this session and a retry action. Browser online status does not guarantee cloud connectivity. Sync uses timestamp-based last-write-wins rather than conflict resolution; a successful sync does not prove that other devices have received changes. Local saves can fail if device storage is full.

Open Clipboard from the launcher or workspace search in a personal workspace. The shelf is local to this device and separated by account or guest; it never syncs or broadcasts to a room. Use Add clipboard to explicitly read the current text (browser permission may be required). Optional capture records selected text copied within Stillspace while it is open, including text fields (excluding password fields), but is paused in shared rooms. It cannot capture copies in other apps or background browsing. It stores up to 20 items of up to 10,000 characters. Clear the shelf to remove them; turning capture off alone does not erase saved entries. Avoid saving passwords or other sensitive content. Device/browser storage and clipboard access can fail.

### Organizing notes and room hand raises
Drag a note card onto a collection in the Notes sidebar to move it. The card becomes a compact preview offset from the pointer, and the destination highlights as you hover; a brief confirmation appears after the move. Reduced-motion settings are respected. On touch devices or without dragging, open the note and use its collection selector instead. Shared notes owned by another participant cannot be moved.

Archive a note using the archive button in its editor; find it under Archive in the Notes sidebar and use the same button to unarchive. Archived notes are excluded from normal lists and workspace search but remain in Archive, account sync, exports, and any app-level room sharing you have enabled. Archiving is not a privacy control and does not cancel reminders. The editor shows body word count, Unicode character count and an approximate reading time at 200 words per minute.

In a shared room, use Raise hand in the shared alert or Participants panel. A raised hand appears next to your name and in the Participants badge; lower it when finished. Hand state is broadcast to everyone with the room code regardless of activity visibility and is reset on leaving. It can take a few seconds to appear and is not a reliable notification when connectivity is interrupted. Participants and room names are not verified.

Clipboard opens inside the launcher; use the arrow to extract it into a movable window and its star to return it to the launcher. Copies from other applications still require the explicit Add clipboard action.

### Tags, find and replace, chat and custom snooze
Add or remove up to 20 tags per note in the editor. Tags are included in note search and appear in the Notes sidebar for filtering; they sync with notes and are shared with a note when app-level sharing is enabled. Archived notes can be found in Archive, not the active tag list.

Use the editor's search button to find case-sensitive text in the body and replace the first or all occurrences. Changes are subject to the existing local note-history limits. Shared notes owned by others remain read-only.

The Chat button in a live room opens a temporary message panel. Messages are broadcast to everyone with the room code regardless of app sharing choices, are not end-to-end encrypted, and are not saved for later arrivals or offline participants. Names are self-selected and unverified. Delivery is best effort; a successful send is not a read receipt. Each open client retains at most 100 messages in memory until it leaves the room. Do not send secrets.

A reminder's Custom snooze opens the existing date and time editor, which supports a custom future time; shared reminders belonging to others remain read-only. Notifications remain dependent on the app being open and browser permissions.

### Room tools and layout links
**Share layout** creates a link to a window arrangement, not a separate account or live shared workspace; the person opening it uses their own workspace and data. **Live room** opens a separate desktop view using the current guest workspace or signed-in account. Each participant chooses which existing app data to share live. Signing in before joining makes that account's data available for selection; it is not imported or cloned into a new profile.

In a live room, **Whiteboard** and **Polls** are available from the shared-workspace banner. The whiteboard broadcasts completed pen strokes while participants are connected; any participant can clear it. Use Save PNG to download your local view before leaving. The board keeps at most 200 strokes locally, each up to 180 points; older strokes are discarded. Polls support two to four options and changing a vote. Each client keeps up to 20 polls for the current room session. Polls and votes, like strokes, are live broadcasts only: late arrivals, reconnecting participants and anyone offline may miss prior events and see a different view or count. Nothing is saved to room storage, and all content disappears from a client on leaving. A successful send is not a delivery guarantee. Names and votes are not verified; anyone with the room code can draw, clear, create polls or vote. These broadcasts pass through Supabase Realtime and are not end-to-end encrypted. Do not use them for sensitive information or consequential decisions.

Room chat uses the same live-room privacy model. The chat panel now groups messages into clearer incoming and outgoing bubbles and retains its existing temporary, best-effort delivery behavior.

### Motion and interaction feedback
Room chat, polls and whiteboard expand from their triggering control and return to it when closed; keyboard focus returns to that control when available. Poll results animate as counts change, and newly shown chat messages, calendar items, tags and clipboard entries have subtle arrival feedback. Chat no longer forces the scroll position to the newest message while you are reading older ones (sending your own message returns to the bottom). Stillspace's Fluid motion setting and the system reduced-motion preference disable these effects.

Notes and Reminders use the same slate icon palette as the other launcher apps. Motion feedback also covers launcher icons, navigation and headings, settings sections, reminder editing, empty states, room controls and focus states. These interactions remain usable with motion disabled, and respect the system reduced-motion preference.


### Cloud storage efficiency
Note and reminder rows store their ID, update timestamp and deletion flag in database columns. New or updated cloud payloads avoid repeating those fields inside the encoded content when that makes the payload smaller, while retaining the existing compatible format and lossless compression. Unchanged edits are not re-uploaded, and fetching uses ordered pages rather than silently stopping at the API row limit. Existing cloud records are not rewritten in bulk; they become compact when next updated. The Settings storage estimate measures encoded payloads, not total database usage or historical backups.

Repeated guest imports now skip items previously copied by this version, even when the account copy is in Recently deleted. Each copy retains a source ID to identify the guest original; it is not a live link and subsequent guest edits do not update the account copy. A successful sync is required before copying, so offline import is not supported. Copies made before this change have no source marker and may still be duplicated; existing records are never automatically merged or deleted. Independently created notes with the same text remain separate, as their owners may intend. Cloud data is still not end-to-end encrypted.

Identical layout links from the same account reuse an existing link. Previously created links remain valid and are not deleted. Layout links belonging to different accounts remain separate.

### Delete notes and reminders without deleting your account
In Account, expand **Delete notes and reminders**, re-enter your password and type DELETE. The server permanently deletes the signed-in account's note and reminder rows (including Recently deleted) in a transaction and checks that none remain. ID-only deletion markers block stale copies of those same IDs from being uploaded again; updated clients remove those items and their note history when they next sync. This doesn't delete the account, appearance settings, shared layout links, guest data, clipboard shelf or content saved by other people. Other devices' offline caches and provider logs/backups may retain copies. Items created offline on another device that were never synced and whose IDs weren't known to the deleting device can still upload later. If the network fails during deletion, the outcome can be uncertain: reconnect and check before retrying. The deletion flow has been build-verified, not independently exercised across devices.

In guest mode, Account offers **Delete guest notes and reminders**, which clears guest items and history from this browser only. It does not affect account data or other devices. Export what you need before deleting; neither deletion can be undone.

App shortcuts now toggle an active app to minimize instead of replaying its opening animation. Minimized frames animate into their dock icon, and restore from it; opening and closing motion uses a softer stretch and merge. Motion preferences and system reduced-motion settings are respected. Room controls and the live-room banner use an updated glass design.

The room setup has separate Create and Join modes, a sharing summary, and an explicit choice for whether new items are shared. Turning off sharing new items keeps them visible and editable to their creator in the room, but does not broadcast them; they remain in the creator's normal workspace. Room settings keep the code, sharing choices and leave/delete actions in one place. The interface respects the motion and reduced-motion settings.

Window opening, closing, minimization, restoration and snap/maximize transitions use a short, continuous morph with a restrained asymmetric pull toward the app icon; maximizing and snapping preserve their animation when the window receives focus. Manual resize follows the pointer rather than lagging behind it, and the resulting size is retained when possible. The window temporarily simplifies backdrop blur during motion to reduce rendering work. Room dialogs use a separately fading dimmer rather than a live full-screen blur, avoiding blur popping and reducing repaint cost. This is a lightweight genie-inspired approximation, not a curved mesh warp. Motion-off and system reduced-motion preferences take precedence.

The Review queue is an intentional list: use the clock button on your own note (or its context menu) to add or remove it, and open Review queue in Notes. The flag is stored with the note and syncs with account notes; it is not included in live-room broadcasts. Archived or deleted notes are hidden from the queue until restored. Other participants' view-only notes cannot be queued.

Window groups are temporary to the current desktop session. Use the taskbar's Window groups button to select at least two existing windows, then minimize and restore the visible members together. Windows already minimized individually remain minimized; a group does not own or delete data. Groups do not persist across reloads, are not shared in layout links, and room groups are separate from the personal desktop. Closing a window removes it from its group. Native text-field and selected-text context menus remain available; elsewhere the desktop navigation menu includes window and note actions when relevant.

### Export and import a backup
Settings → Data & account and workspace search offer an unencrypted JSON export and JSON backup import. Export includes non-deleted notes (including archived notes), standalone reminders, tags, review flags, favorites and reminder state. It excludes local history, deleted items, preferences, clipboard contents and window groups. In a room, export includes all currently visible room items, including other participants’ shared content, and asks for confirmation.

Import is available only in the personal workspace for Stillspace v1 JSON exports up to 10 MiB and 5,000 items. It validates the whole file before writing, asks for confirmation and creates new IDs and new copies; repeated imports create duplicates. It does not merge or replace existing items or restore history. Due imported reminders may notify. The import is first saved on this browser; account sync follows its normal last-write-wins behavior. Storage quotas can prevent import. Older exports cannot restore metadata they never contained. Keep the unencrypted backup private and independently verify important backups.

### Focus a group and compare notes
In **Window groups**, choose **Focus** beside a group to bring its members forward and temporarily minimize other visible windows. Choose **Return to previous windows** in the banner (or **Unfocus** in the group menu) to reverse those changes. Windows that were already minimized outside the group stay minimized; group windows that were minimized before focus return to that state. If you manually minimize, restore or close a window during focus, that window is left in the state you chose. Newly opened windows are not automatically hidden or closed. Groups and focus are temporary, local to the current desktop and not shared.

In Notes, choose **Compare notes**, select two different active notes, and open them side by side. The notes remain independent editable or view-only windows according to normal permissions; no data is copied. Use **Return to previous positions** to restore the earlier window geometry. Notes opened specifically for comparison remain open, and manually minimized windows stay minimized. Closing a note excludes that window from restoration. Comparison requires a screen wider than 700 pixels; on a narrower resize it ends and restores the prior geometry. On other viewport resizes the pair retiles. Group focus and comparison cannot run together; finish the current mode before joining a room. Leaving a room ends its temporary modes. Both modes respect the motion setting and system reduced-motion preference.
